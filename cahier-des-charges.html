01

Philosophie & Positionnement

Une invitation digitale n'est pas un flyer numérisé. C'est une expérience — la première que vivra l'invité avant le mariage. Elle doit provoquer une émotion, pas seulement transmettre une information.

Les 3 piliers inviolables

ÉMOTION D'ABORD. Chaque décision de design — espacement, typographie, animation — doit se justifier par l'émotion qu'elle produit. Si ça ne fait pas "WOW", c'est à retravailler.

MOBILE PARFAIT. 95 % des invités ouvriront l'invitation sur smartphone. Le design mobile n'est pas une version dégradée — c'est la version principale.

ZÉRO COMPROMIS SUR LA QUALITÉ. Un seul élément cassé (texte coupé, bouton invisible, image floue) détruit la perception de toute l'invitation. Tester sur 5 appareils minimum avant livraison.

Ce que The Digital Yes fait et que nous devons reproduire

Principe TDYTraduction concrète
RespirationChaque section respire : padding 90–140px vertical. Le blanc n'est pas du vide, c'est du luxe.

Système de Design Universel

2.1 — Typographie

Deux Google Fonts maximum par invitation. La combinaison obligatoire :

Font Display — Titres, Noms des mariés

Cormorant Garamond

Usage : h1, h2, es-title, noms des mariés, citations · Weight 300 (light italic)

Font Kicker — Labels, Boutons, Navigation

CINZEL

Usage : kickers, étiquettes, uppercase labels, numéros romains · Weight 400

Font Corps — Textes courants, Sous-titres

Tenor Sans

Usage : paragraphes, descriptions, boutons CTA · Weight 400

Interdiction absolue : Ne jamais utiliser plus de 3 familles de polices dans une même invitation. Pas d'Arial, pas de Roboto, pas de Open Sans — trop génériques, détruisent le prestige.

Règle absolue : Une invitation = 1 fichier HTML, 1 bloc <style> consolidé, 1 bloc <script> principal. Pas de CSS éparpillé en 8 blocs. Pas de !important sans raison documentée.

4.4 — Performance — Règles strictes

  • Toutes les images hors viewport ont loading="lazy"
  • La photo hero et les images above-the-fold ont loading="eager"
  • Les iframes (timeline, countdown, scratch) ont loading="lazy"
  • Pas d'animation will-change sur plus de 5 éléments simultanément
  • Aucune animation CSS sur width, height, top, left — uniquement transform et opacity
  • Police chargée via Google Fonts avec display=swap
  • Musique : preload="none" — chargement uniquement au clic

Animations & Interactions

5.1 — Scroll Reveal (OBLIGATOIRE sur toutes les invitations)

La signature visuelle de TDY. Chaque contenu entre dans l'écran avec une transition douce. Ce système doit être présent dans 100% des invitations.

/* CSS — États du scroll reveal */
.ev-reveal {
  opacity: 0;
  transform: translateY(36px);
  transition:
    opacity  0.9s cubic-bezier(0.16, 1, 0.3, 1),
    transform 0.9s cubic-bezier(0.16, 1, 0.3, 1);
  will-change: opacity, transform;
}
.ev-reveal.ev-visible {
  opacity: 1;
  transform: translateY(0);
}
/* Délais de stagger pour groupe d'éléments */
.ev-d1 { transition-delay: 0.10s; }
.ev-d2 { transition-delay: 0.20s; }
.ev-d3 { transition-delay: 0.32s; }
.ev-d4 { transition-delay: 0.46s; }
/* JS — IntersectionObserver (à inclure dans chaque invitation) */
(function() {
  'use strict';
  var TARGETS = '.es-kicker, .es-title, .date-title-line-main, ' +
    '.es-copy, .place-v09, .c3-item.is-active, .gift-accord-item, ' +
    '.countdown-title, .gifts-presence-phrase, .final-couple, ' +
    '.thanks-copy-main, .act-tabs';

  function init() {
    if (!('IntersectionObserver' in window)) return;
    var obs = new IntersectionObserver(function(entries) {
      entries.forEach(function(e) {
        if (!e.isIntersecting) return;
        var delay = e.target._evDelay || 0;
        setTimeout(function() {
          e.target.classList.add('ev-visible');
        }, delay);
        obs.unobserve(e.target);
      });
    }, { threshold: 0.08, rootMargin: '0px 0px -48px 0px' });

    document.querySelectorAll(TARGETS).forEach(function(el) {
      var rect = el.getBoundingClientRect();
      if (rect.top < window.innerHeight * 0.92) return; /* déjà visible */
      el._evDelay = 0; /* calculer si nécessaire */
      el.classList.add('ev-reveal');
      obs.observe(el);
    });
  }

  document.readyState === 'loading'
    ? document.addEventListener('DOMContentLoaded', function() { setTimeout(init, 120); })
    : setTimeout(init, 120);
})();

Responsive — Règles Strictes

Le responsive n'est pas une option. C'est la version principale. Le design se conçoit d'abord pour iPhone 14 Pro (390px), puis s'adapte vers le haut.

6.1 — Breakpoints obligatoires

/* Mobile portrait — point de départ (390px) */
/* AUCUN media query = design mobile */

/* Tablette */
@media (min-width: 768px) {
  /* 2 colonnes possibles, padding augmenté */
}

/* Laptop / Desktop */
@media (min-width: 1024px) {
  /* Layouts 2-3 colonnes, max-width 960px centré */
}

/* Grand écran */
@media (min-width: 1280px) {
  /* Rarement nécessaire — max-width suffit */
}

6.2 — Typographie fluide — TOUJOURS clamp()

Règle stricte : Aucune taille de police fixe sur les titres, kickers, ou copy. Tout doit utiliser clamp(min, valeur-fluide, max). Une taille fixe en px = un bug sur un autre écran.

/* ✓ BON — adaptatif */
.es-title { font-size: clamp(30px, 8.5vw, 70px); }
.es-copy  { font-size: clamp(15px, 3.2vw, 22px); }
.es-kicker{ font-size: clamp(9px,  1.8vw, 11.5px); }

/* ✗ MAUVAIS — fixe, cassera sur un autre écran */
.es-title { font-size: 48px; }
.es-copy  { font-size: 18px; }

Ce qu'on supprime absolument

Ces erreurs reviennent dans toutes les premières versions. Les identifier et les éliminer avant livraison :

  • CSS fragmenté en 5+ blocs <style> — chaque session ajoute un nouveau bloc au lieu de modifier l'existant. Résultat : conflits de spécificité, maintenance impossible, fichier ingérable.
  • !important sur tout — quand tout est !important, rien ne l'est. Réserver aux overrides légitimes uniquement (< 10% des règles).
  • Sections sans padding vertical suffisant — padding inférieur à 60px sur une section standard. Le blanc est du luxe, pas du vide à remplir.
  • Textes trop petits sur mobile — toute taille de police < 14px pour du corps de texte sur mobile est une erreur d'accessibilité ET d'élégance.
  • Polices sans fallback — toujours mettre serif ou sans-serif en fallback après la Google Font.
  • Images sans dimensions — provoquer du layout shift (CLS) dégradant la note PageSpeed et l'UX perçue.
  • Boutons sans hover/focus state — un bouton statique semble cassé sur desktop. Toujours une transition au hover.
  • JavaScript dupliqué — même fonction déclarée 2x dans le même fichier (ex: fitRomans déclarée dans 2 blocs <script> distincts).
  • Sections vides ou placeholders — jamais livrer avec des "#", des "Lorem ipsum", des boutons qui ne font rien.
  • Scroll horizontal — tout élément qui dépasse la largeur de l'écran est une erreur critique. Tester avec overflow-x: hidden sur body si nécessaire.
  • Couleurs incohérentes — utiliser 4 valeurs différentes pour "le gold" dans le même fichier. Tout passe par les variables CSS :root.
  • Animations qui tournent dans le vide — animations infinite sur des éléments hors viewport qui consomment du CPU inutilement. Utiliser IntersectionObserver pour les activer/désactiver.

Checklist Qualité — Avant Livraison

À valider sur au minimum 3 appareils réels (iPhone, Android, Desktop) avant tout envoi au client.

Design & Typographie

  • Tous les titres utilisent Cormorant Garamond, poids 300
  • Tous les kickers utilisent Cinzel, uppercase, letter-spacing 0.4em+
  • La couleur or est partout la même (variable --ev-gold)
  • Chaque section a un séparateur or principal + secondaire sous le titre
  • Le padding vertical de chaque section est ≥ 60px (idéal 90–140px)
  • La largeur max du contenu est ≤ 960px et centré
  • Aucun texte ne sort de son container (débordement horizontal = BLOQUANT)

Animations & Scroll

  • Le scroll reveal est activé sur kicker, titre, séparateurs, copy de chaque section
  • Les animations au scroll sont douces (≥ 0.7s, cubic-bezier(0.16,1,0.3,1))
  • La porte d'entrée fonctionne (CTA visible, transition fluide vers le hero)
  • Les sparkles du hero sont visibles mais non envahissants
  • Le shimmer or sur les noms finaux fonctionne sur Safari iOS
  • Les animations d'entrée ne "flashent" pas (pas de FOUC)

Fonctionnalités

  • La musique se lance au clic et peut être coupée
  • Le changement de langue FR/EN fonctionne sur toutes les sections
  • La navigation dots latérale pointe vers les bonnes sections
  • Les carousels de lieux fonctionnent (flèches, auto-slide si activé)
  • Le carousel hébergements fonctionne
  • Les onglets d'activités basculent correctement
  • L'accordéon cadeaux s'ouvre et se ferme
  • Le RSVP envoie les données et affiche la confirmation
  • Le bouton "Ajouter au calendrier" télécharge le .ics
  • Tous les liens Maps s'ouvrent (tester sur mobile)

Responsive

  • Aucun scroll horizontal sur iPhone SE (375px)
  • Tous les boutons ont une zone cliquable ≥ 44×44px
  • Les images ne débordent pas de leur container
  • Les noms des mariés sont entiers et lisibles sur 375px
  • Le formulaire RSVP est utilisable sur mobile
  • Les onglets/tabs s'affichent correctement sur petit écran
  • La police ne rétrécit pas sous 14px sur mobile (iOS text-size-adjust: 100%)

Performance & Technique

  • Toutes les images hors viewport ont loading="lazy"
  • Le fichier HTML fait moins de 1 MB (idéal < 700 KB hors images)
  • netlify.toml est présent avec les Cache-Control corrects
  • Le titre HTML contient le numéro de version (ex: · v30)
  • Aucun chemin d'image cassé (404)
  • Les iframes (timeline, countdown, scratch) chargent correctement
  • Le site fonctionne sans JS (contenu visible, pas d'écran blanc)
